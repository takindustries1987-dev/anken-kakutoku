## Step 1: 01_profileの読み解き方

01_profileフォルダには性格診断・占術を統合した自己理解データが入っている。案件獲得では「強み」「仕事スタイル」「事故りパターン」を抽出して使う。

### 各ファイルと抽出すべき情報

| ファイル | 何を抽出するか | 使い先 |
|---------|---------------|--------|
| `私の性格プロファイル.md` | 強み（§2）、判断軸（§2末）、仕事スタイル（§6） | プロフィール文・応募文・セルフマネジメント |
| `ENFJ_特徴まとめ_実務版.md` | 伝達力・推進力の具体表現（§2）、スコープ固定テンプレ（§6-2） | プロフィール文、案件進行時のDone定義 |
| `big5_score.md` | 武器（構想力・対人推進）、ボトルネック（習慣化の弱さ・不安由来の停止）（§3） | 自分の行動設計、落とし穴チェックリスト |
| `2026年_行動計画.md` | 月別の攻め/守り判断（§3）、やる/やらないリスト（§5） | 案件選定の判断軸、キャパ管理 |
| `四柱推命_report.md` | 合意形成の型、単価設計、正論の丸め方 | 案件進行、クライアント対応 |
| `算命学.md` | 条件を紙にする、一本化、選別と単価設計 | 案件選定、スコープ管理 |
| `六星占術_水星人(-)_2026.md` | 月別の運気（攻め/守り） | スケジュール調整の参考 |
| `animal_fortune_lion_master.md` | 礼節・品質・プライドの扱い | 対人スタイルの言語化 |

### 抽出の手順

1. `私の性格プロファイル.md` の §2（強み）から**仕事・成果に直結する強み**を3〜5つピックアップ
2. `ENFJ_特徴まとめ_実務版.md` の §2 から**クライアントに響く表現**（伝達力・推進力・仕組み化）を確認
3. `big5_score.md` の §3 から**武器とボトルネック**を把握 → 落とし穴チェックリスト（Step 6）に反映
4. 上記を元に「自分の強み＝クライアントにとっての価値」に翻訳する

### 「強み → クライアント価値」変換テーブル

| プロファイルの強み | クライアントにとっての価値 | プロフィールでの表現例 |
|-------------------|------------------------|---------------------|
| 伝達力（ENFJ） | 要件の認識ずれが起きにくい | 「要件を丁寧にヒアリングし、認識齟齬のない進行を心がけます」 |
| 推進力（ENFJ） | 期限通りに完了する | 「スケジュールを明確にし、納期厳守で対応します」 |
| 仕組み化（Ni） | 再利用・改善しやすい成果物 | 「運用しやすいコード/仕組みを意識して納品します」 |
| 責任感（ライオン） | 中途半端にしない | 「最後まで責任を持って対応します」 |
| 観察眼（水星人） | 課題の本質を素早く把握 | 「課題を的確に把握し、最短距離でのご提案を行います」 |
| 文書化（四柱推命） | 進捗・仕様が可視化される | 「進捗報告・仕様書を都度共有いたします」 |
| 構想力（Big5） | 新しい切り口・改善提案 | 「現状分析から改善提案まで一貫して対応可能です」 |

## Step 2: プロフィール文面の組み立て方

### 抽出すべき4要素

| 要素 | 内容 | ソース |
|------|------|--------|
| **強み** | 自分がクライアントに提供できる価値 | Step 1の変換テーブル |
| **実績** | 過去にやった仕事、スキル証明 | 自分の経歴（空欄に記入） |
| **対応可能範囲** | できること・使える技術 | 自分のスキルセット |
| **仕事の進め方** | コミュニケーション・納品スタイル | プロファイルの仕事スタイル |

### PFごとの文字数制限・推奨構成

#### CrowdWorks（自己PR：最大2,000文字）

```
【構成】
1. 冒頭あいさつ + 一言自己紹介（2〜3行）
2. 対応可能な業務（箇条書き 5〜8項目）
3. 使用スキル・ツール（箇条書き）
4. 実績・経歴（2〜3項目）
5. 仕事の進め方・大切にしていること（3〜4行）
6. 稼働時間・連絡手段
```

#### ココナラ（自己紹介：最大2,000文字）

```
【構成】
1. 冒頭あいさつ + 肩書き（1〜2行）
2. こんな方におすすめ（3〜5項目）
3. 提供できるサービス（箇条書き）
4. 実績・経歴
5. 仕事の進め方（購入者目線で安心ポイント）
6. 対応時間・ご連絡について
```

#### ランサーズ（自己紹介：最大2,000文字）

```
【構成】
1. 冒頭あいさつ + 専門分野（2行）
2. できること（箇条書き 5〜8項目）
3. 使用技術・ツール
4. 実績・経歴
5. 仕事への姿勢（プロファイルの強み→価値に変換）
6. 稼働可能時間・連絡方法
```

### プロフィール文面テンプレート（空欄形式）

以下のテンプレートの `{  }` 部分を自分の情報で埋める。

```
プロフィールをご覧いただきありがとうございます。
{ 肩書き / 一言自己紹介 }です。

■ 対応可能な業務

■ 使用スキル・ツール

{ その他 }：{ Google Sheets / スプレッドシート / Notion 等 }

・{ 実績1（例：○○業界でのデータ自動収集ツール開発 → 月XX時間の工数削減） }

・稼働時間：平日 { 時間帯 }、土日 { 対応可否 }
・連絡手段：{ チャットワーク / メッセージ / Slack 等 }
・レスポンス：原則 { 24時間以内 / 当日中 } に返信
```

## Step 3: ココナラ出品の手順

### 3-1. 出品の流れ

1. ログイン → 「出品する」をクリック
2. サービスの種類を選択：
   - **通常サービス**（一番使う）：価格を決めて出品
   - **電話相談**：電話で相談を受ける形式
   - **ビデオチャット**：オンライン面談形式
3. カテゴリを選択（例：IT・プログラミング → ソフトウェア・業務システム開発）
4. サービス内容を入力

### 3-2. サービス出品時の入力項目

| 項目 | 内容 | ポイント |
|------|------|---------|
| **サービスタイトル** | 最大25文字 | 「何をしてくれるか」が一目でわかるように |
| **タイトル補足（キャッチコピー）** | 最大35文字 | 購入者のメリットを書く |
| **サービス内容** | 最大2,000文字 | 下記テンプレート参照 |
| **カテゴリ** | 1つ選択 | 自分のスキルに合うものを |
| **サービス価格** | 最低1,000円〜 | 初期は低めに設定→実績を積んで上げる |
| **提供形式** | テキスト/PDF/ファイル等 | 成果物の形式を明記 |
| **お届け日数** | 1〜30日 | 短いほど購入されやすいが無理は禁物 |
| **購入にあたってのお願い** | 自由記述 | 必要な情報を書く |
| **一度に受注可能な件数** | 1〜20件 | 最初は1〜3件に設定 |
| **有料オプション** | 任意 | 追加対応を有料化できる |
| **サービス画像** | 最大10枚 | 目を引くサムネイルを設定 |

### 3-3. サービス内容テンプレート

```
{ サービスの概要を2〜3行で }

■ こんな方におすすめ
・{ ターゲット1（例：手作業でデータをコピペしている方） }
・{ ターゲット2（例：毎月のレポート作成を自動化したい方） }
・{ ターゲット3（例：AIを使った業務改善に興味がある方） }

■ 提供内容
・{ 内容1（例：ご指定のWebサイトからデータを自動取得するツールを開発） }
・{ 内容2（例：取得データをスプレッドシートに自動出力） }
・{ 内容3（例：使い方マニュアルを付属） }

■ 料金に含まれるもの
・{ 含むもの1（例：ツール本体（Pythonスクリプト）） }
・{ 含むもの2（例：簡易マニュアル） }
・{ 含むもの3（例：納品後7日間の修正対応） }

■ 料金に含まれないもの（オプション対応可）
・{ 含まないもの1（例：対象サイトの追加（1サイト+○○円）） }
・{ 含まないもの2（例：定期実行の設定（サーバー構築含む）） }

■ ご購入の流れ
1. ご購入前にメッセージでご要件をお聞かせください
2. 対応可否・見積もりをご連絡します
3. ご購入後、詳細ヒアリング
4. 開発 → 途中経過のご報告
5. 納品 → 動作確認 → クローズ

■ 納期
・通常 { X }営業日以内
・内容により変動しますので、事前にご相談ください

■ 注意事項
・{ 注意1（例：対象サイトの利用規約に反するスクレイピングはお受けできません） }
・{ 注意2（例：納品後の大幅な仕様変更は追加料金が発生します） }
```

### 3-4. 出品のコツ

- **初期は相場より少し安めに設定** → 実績0の状態で相場価格は売れない
- **タイトルに「何をするか」を具体的に** → 「プログラミングします」×  「Webスクレイピングツールを作成します」○
- **サムネイル画像は自作** → Canva等で「何ができるか」を視覚化
- **購入前の相談を促す** → 「まずはメッセージでご相談ください」を入れる
- **出品直後は検索上位に出やすい** → 公開前に内容を完成させておく

## Step 4: CW/ランサーズの案件応募手順

### 4-1. 案件検索の流れ

#### CrowdWorks

1. ログイン → 「仕事を探す」
2. カテゴリで絞り込み（例：Web開発、システム開発、データ入力）
3. フィルター設定：
   - 契約形式：固定報酬制 / 時間単価制
   - 報酬額：下限を設定
   - 応募期限：まだ締め切っていないもの
   - ステータス：募集中のみ
4. キーワード検索も併用（例：「Python」「GAS」「スクレイピング」「自動化」）

**→ または `daily_job_scraper.py` でスクレイピング済みCSVから探す**

#### ランサーズ

1. ログイン → 「仕事を探す」
2. カテゴリで絞り込み（例：Web制作・Webデザイン、システム開発・運用）
3. フィルター設定：
   - 依頼形式：プロジェクト / コンペ / タスク
   - 報酬：下限を設定
   - 募集状況：募集中
4. キーワード検索併用

### 4-2. 応募する案件の選定基準

プロファイルの判断軸（長期的信頼 > 収益性 > スケーラビリティ）を適用する。

#### 応募すべき案件

- [ ] 自分のスキルで対応可能
- [ ] 要件が具体的（成果物・期限が明確）
- [ ] 報酬が妥当（時間単価換算で最低ラインを上回る）
- [ ] クライアントの評価が良い（過去の発注実績・評価を確認）
- [ ] 納期に余裕がある（キャパオーバーにならない）

#### 避けるべき案件（プロファイルの「事故りパターン」に基づく）

- 要件が「とりあえず相談」「なんとなく」で具体性ゼロ
- 予算が「応相談」で極端に安い可能性
- クライアントの評価が低い / 発注実績なし
- 「急募」かつ納期が非現実的
- 範囲が「一式」「全部やって」系で境界が不明

### 4-3. 応募文の作成

#### 応募文テンプレート（共通ベース）

```
{ クライアント名 } 様

はじめまして、{ 自分の名前 }と申します。
{ 案件名 }のご依頼を拝見し、ご応募させていただきます。

■ 対応可能な理由
・{ 関連スキル/実績1（例：Pythonでのスクレイピング開発を複数件対応しております） }
・{ 関連スキル/実績2 }

■ ご提案内容
{ 案件の要件に対する具体的なアプローチを2〜3行で }

■ 納期
・{ X }営業日以内（ご相談可能です）

■ お見積もり
・{ 金額 }円（税込）
・{ 含む範囲 }

■ 進め方
1. ご発注後、詳細要件のヒアリング
2. 仕様確認・スケジュール共有
3. 開発 → 途中経過のご報告
4. 納品 → 動作確認 → 修正対応

■ 稼働について
・レスポンス：原則24時間以内
・稼働時間：{ 平日○時〜○時 }

ご不明な点がございましたら、お気軽にご連絡ください。
ご検討のほど、よろしくお願いいたします。
```

#### 応募文のカスタマイズポイント

1. **冒頭で「なぜ自分が適任か」を1〜2行で**（流し見でも刺さるように）
2. **案件の要件を自分の言葉で言い換える**（「理解しています」のアピール）
3. **具体的な実績を1〜2個だけ**（長すぎると読まれない）
4. **金額・納期は明確に**（曖昧だと比較検討から外される）
5. **テンプレ感を消す**（案件ごとに冒頭2〜3行をカスタム）

### 4-4. 応募後のフォロー

- 応募後3日経っても返信がない → 催促は不要（クライアントのペースを尊重）
- クライアントから質問が来た → **24時間以内に返信**（レスポンスの速さが評価に直結）
- 見積もり相談が来た → スコープ固定テンプレ（ENFJ実務版§6-2）を使って条件を明確に

## Step 5: 案件獲得後の進め方

### 5-1. 受注〜納品のフロー

```
1. 受注確定
   ↓
2. 要件確認（キックオフ）
   ↓
3. スコープ固定（合意形成）
   ↓
4. 開発（途中報告を入れる）
   ↓
5. 納品
   ↓
6. クライアント検収
   ↓
7. 修正対応（必要な場合）
   ↓
8. 検収完了
   ↓
9. 出金
```

### 5-2. 要件確認（キックオフ）— スコープ固定テンプレを使う

受注直後に、プロファイルの「スコープ固定テンプレ」を使って以下を確認・合意する。

```
■ 確認事項テンプレ（初回メッセージ）

お世話になっております。{ 名前 }です。
ご発注いただきありがとうございます。

スムーズに進めるため、以下の内容を確認させてください。

【依頼内容】
{ クライアントの要件を自分の言葉で要約 }

【成果物】
{ 最終的に何を納品するか（ファイル形式含む） }

【対象外（今回含まないもの）】
{ 明確にスコープ外にすること }

【期限】
{ 納品予定日 }

【追加変更の扱い】
開発開始後の仕様変更・追加は別途お見積もりとさせていただきます。

上記の内容で問題なければ、開発に着手いたします。
ご確認のほど、よろしくお願いいたします。
```

**なぜこれが大事か**（プロファイルより）
- ENFJの落とし穴「"納得"優先で定義が曖昧なまま走る」→ 後で手戻り・炎上
- 算命学「ノリで始まり運用設計がない案件」→ 崩壊パターン
- 四柱推命「条件を紙にする」→ 最初に決めると勝つ

### 5-3. 開発中のコミュニケーション

- **進捗報告のタイミング**：
  - 着手報告（開始日）
  - 中間報告（全体の50%時点）
  - 完了間近の報告（納品1〜2日前）
- **報告のフォーマット**：
  ```
  ■ 進捗報告
  ・完了した作業：{ }
  ・現在進行中：{ }
  ・残りの作業：{ }
  ・懸念点/ご相談：{ あれば }
  ・予定納品日：{ 変更なし / 変更あり → 理由 }
  ```
- **追加要望が来た場合**：
  - 即答で「やります」と言わない（抱え込み防止）
  - 「確認します。現在のスコープとの兼ね合いを見て、対応可否とお見積もりをお伝えします」と返す

### 5-4. 納品

- **納品物のチェックリスト**：
  - [ ] 動作確認済み
  - [ ] 要件書/スコープに記載した内容をすべてカバーしている
  - [ ] 簡易マニュアル or README を添付（使い方がわかる状態で納品）
  - [ ] テスト結果・動作画面のスクリーンショットを添付
- **納品メッセージ**：
  ```
  お世話になっております。{ 名前 }です。

  開発が完了しましたので、納品いたします。

  ■ 納品物
  ・{ ファイル名/形式 }

  ■ 動作確認
  ・{ 確認した環境・手順 }

  ■ 使い方
  ・{ 簡易手順 or マニュアル参照先 }

  ■ 修正対応
  ・納品後{ X }日間は無料で修正対応いたします

  ご確認いただき、問題なければ検収完了をお願いいたします。
  不明な点がございましたらお気軽にご連絡ください。
  ```

### 5-5. 検収〜出金

- **検収完了の催促**（3日経っても検収されない場合）：
  ```
  お世話になっております。
  先日納品させていただいた件ですが、ご確認状況はいかがでしょうか。
  ```

## Step 6: 落とし穴チェックリスト

01_profileの「事故りパターン」を案件獲得に当てはめた注意点。

### 案件選定時の落とし穴

| # | パターン | プロファイル根拠 | 対策 |
|---|---------|----------------|------|
| 1 | **「面白そう」で案件を増やしすぎる** | ENFJ：シャイニーオブジェクト（Se刺激に引っ張られる） | 週の上位3つルール。新案件は「保留箱」→ 週1レビューで判断 |

| 3 | **低単価案件を大量に受けてしまう** | 協調性高め（A71）：頼まれると断りづらい | 時間単価の最低ラインを決めておく。「この金額以下は受けない」をルール化 |
