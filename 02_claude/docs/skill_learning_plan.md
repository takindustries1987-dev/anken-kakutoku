# 案件獲得のための学習プラン

`market_public_stats.md` とポジショニングマップの分析、および `01_profile` の性格・強みプロファイル
（仕組み化・業務設計・伝達力・推進力・文書化が強み、深い専門コーディングは中核の強みではない）を
踏まえた学習ロードマップ。

## 前提となる自己分析サマリー

- 強み: 仕組み化・SOP/手順書設計、伝達力（相手が動ける言い方への翻訳）、推進力（合意形成して前進）、
  文書化・証跡（議事録・提案書）、条件の明文化（範囲・期限・報酬を先に決める）
- 注意点: 不安・完璧主義による着手遅れの傾向あり → 小さく区切った学習目標と締切設定が合う
- 面談メモより: プログラミングは「モジュールの組み合わせでツールができる」という理解はすでにある。
  企業に正社員として入るなら本格的なプログラミング力が必要だが、コンサル・業務委託中心で行くなら
  「使いこなす力」で十分という認識。

→ **深い専門エンジニアリングよりも「AI・ノーコードツールを使い倒して業務を仕組み化し、
それを言語化・提案できる」ポジションを狙うのが強みに合う。**

## ポジショニングマップとの対応

| ゾーン | 該当プラットフォーム | 狙い方 |
|---|---|---|
| 入門・実績作り（低単価・低参入障壁） | CrowdWorks・ランサーズ・ココナラ | 小さいツール開発案件で実績とレビューを積む。単価より件数・実績重視 |
| 中間（審査あり・継続稼働） | 複業クラウド・Workship・フリーランススタート | 実績を基に「業務自動化・DX支援」枠で応募 |
| 専門性で稼ぐ（高単価・高難易度） | サンカク・SOKUDAN・コンパスシェア(ConPath) | 業務設計・DX推進・AI活用コンサルとして提案型で参入 |
| 人脈・カルチャー型 | Wantedly・YOUTRUST・LinkedIn | 発信・カジュアル面談で中長期の関係構築を並行 |

## Phase 1（0〜4週）: 基礎固め・実績の種まき

**目標**: CrowdWorks/ランサーズで小型の業務自動化案件を2〜3件受注・納品する

- Python基礎（変数・関数・ライブラリ利用の型を復習。既存モジュールの組み合わせ方に慣れる）
- GAS（Google Apps Script）・Excelマクロ/VBA の基本パターン（スプレッドシート連携、定型作業の自動化）
- ChatGPT API / Claude API の基本的な呼び出し方（既存の `02_claude/portfolio/chatgpt_api_demo.py` を参考に）
- 毎朝 `daily_job_scraper.py` を実行し、業務自動化・GAS・Excel関連の小型案件に応募する運用を回す

## Phase 2（1〜2ヶ月）: 型化とポートフォリオ化

**目標**: 「要件ヒアリング→SOP化→ツール実装→運用引き継ぎ」の型を2〜3件分の事例として言語化する

- 納品した案件を「Before/After」「削減できた工数」の形で事例化（強みの文書化・言語化を活かす）
- ノーコード自動化ツール（Zapier/Make等）の基本操作を押さえ、GAS/Pythonと使い分けられるようにする
- 簡易データ分析（pandasでのExcel/CSV集計・可視化）を1つ覚え、「分析込みの業務改善提案」ができるようにする
- 複業クラウド・Workship・フリーランススタートで「業務効率化」「DX推進」系の案件に応募開始

## Phase 3（2〜3ヶ月）: 差別化・高単価領域への接続

**目標**: サンカク・SOKUDAN・コンパスシェア(ConPath)クラスの案件に提案できる実績パッケージを作る

- Phase 2の事例を使って「AI活用研修」「業務自動化コンサル」の提案書テンプレートを作成
  （面談メモにあった「既存ビジネス研修にAIを組み込む」方向性と合致）
- 提案書・事例集は伝達力・文書化の強みを最大限使う領域なので優先的に時間を割く
- サンカク（月5〜10万円中心のDX推進案件）・複業クラウド（時給ベースの継続案件）に応募し、
  「ツール実装だけでなく仕組み化・運用設計までできる人」として差別化する

## Phase 4（継続）: 人脈・発信の並行運用

- Wantedly・YOUTRUSTでのカジュアル面談・スカウト対応は工数を決めて（例: 週1時間）並行運用
- SNS発信（`01_profile/SNS用.md` 参照）でAI活用・業務効率化の知見を継続発信し、
  YOUTRUST/LinkedIn経由の中長期の関係構築につなげる

## 学習の進め方に関する注意（自己分析より）

- 完璧主義・不安による着手遅れの傾向があるため、各Phaseの目標は「小さく・締切つき」で区切る
- KPI／Done基準を先に決めてから着手すると強みが最大化するタイプなので、
  各案件・学習項目に「完了の定義」を一言でも書いてから始める
