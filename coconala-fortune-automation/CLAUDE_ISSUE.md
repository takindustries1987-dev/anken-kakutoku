## [2026-08-16] ココナラへの実ログイン・自動操作が未実装

### 問題
`src/coconala_client.py` の `CoconalaClient` は抽象インターフェースのみで、
実際にココナラへログインして注文検知・メッセージ送信・納品・評価依頼投稿・評価取得・評価返信を
行う具象クラスが存在しない(`NotImplementedCoconalaClient` が全メソッドで
`NotImplementedError` を送出する)。

### 原因
- ココナラには出品者向けの公式APIが存在しない。
- ユーザーの意向により、今回のセッションでは「まずは設計・コードの枠組みだけ作る」ことを
  優先し、実ログイン情報を使った本番接続は次の段階に持ち越すことになった。

### 対応策(未実施・要検討)
1. **Playwright によるブラウザ自動操作**: `COCONALA_EMAIL` / `COCONALA_PASSWORD` で
   ログインし、注文一覧ページ・トークルーム・評価ページを操作する。ログインセッションの
   永続化(Cookie保存)や2段階認証への対応も検討が必要。
2. **利用規約の確認**: ココナラの利用規約でbot・自動操作が制限されている可能性がある。
   実装・運用前に必ず確認し、規約違反となる場合は本方針自体を見直す必要がある
   (アカウント停止リスクがあるため)。
3. **メール通知の併用**: ココナラは新着メッセージ・評価をメール通知するため、
   Gmail連携(検知トリガー)と組み合わせることで、ブラウザ操作の頻度を減らせる可能性がある。

### 暫定動作
- `python -m src.main` は `NotImplementedCoconalaClient` を使うため、実行すると即座に
  `NotImplementedError` で停止する。誤って未実装のまま本番運用が始まることはない。

## [2026-08-16] 鑑定ロジック・出品文言が未反映(プレースホルダーのまま)

### 問題
`config/fortune_service_content.py`(鑑定方針)と `src/message_templates.py`(各種文言)は、
ユーザーが別途ローカルフォルダに持っている実際の出品内容を反映できておらず、
汎用的な仮の内容になっている。

### 原因
このセッションはリモート実行環境であり、ユーザーのローカルマシン上のフォルダには
アクセスできなかった。

### 対応策
- README.md の「テンプレート内容の差し替え」の手順に従い、ユーザーが実データを
  貼り付ける形で `config/fortune_service_content.py` と `src/message_templates.py` を
  更新する。

## [2026-08-16] GitHub連携に新規リポジトリ作成権限がない

### 問題
このセッションのGitHub連携(GitHub App)は、既存リポジトリへの読み書き権限はあるが
新規リポジトリの作成権限(Administration権限)を持たず、`mcp__github__create_repository`
が `403 Resource not accessible by integration` で失敗する。

### 対応策
- ユーザーが GitHub 上で空のリポジトリを作成し、このセッションから `add_repo` で
  アクセス権を得てから push する。
- または既存リポジトリ(`anken-kakutoku` など)内のサブフォルダとして運用する。

### 暫定動作
- 本プロジェクトはローカル(`git init` 済み)で一式構築済み。リポジトリの置き場所が
  決まり次第、リモートを設定して push する。
